# Optional phone module security model

The protocol grants an exclusive bearer capability, not an authenticated account identity. Stdio and secure tunnel requests do not supply a verified per-request human principal here. lease_id is 256 random bits; the server persists only its hash. Do not share it, log it, or pass it as an owner label. All processes serving this physical serial must share one administrator-protected local state_dir. A second state directory or a different ADB client is outside this protocol's exclusion guarantee. The administrator controls this deployment invariant.

An atomic directory lock serializes device probes, writes, lease updates and generic host commands across processes. Lock contention returns promptly rather than building an unbounded queue. A live operation renews its short lease; idle leases expire. Slow operations retain the device lock even if a lease deadline passes, and cannot revive an expired capability at completion. Windows process death leaves a fail-closed lock. Administrator recovery requires pause, all related stdio processes stopped, and a dead owner PID; there is no automatic age-based takeover. See the [deployment guide](phone-legion-deployment.md) for executable commands and PID-reuse handling.

Before dispatching an irreversible command, the service fsyncs a pending request receipt and atomically renames it into place. request_id maps to a durable receipt and an HMAC of validated arguments, keyed by the lease capability; plaintext input is absent. Matching retries return completed metadata or outcome_unknown without sending another command. Reusing an ID with different arguments or a different capability is rejected. Response images are never persisted or replayed. A dispatch failure, lost connection, crash, or failure to observe/save the result leaves pending, because the device may already have applied the command. Inspect the device and original request before deciding any further action; a new ID is not a retry mechanism for payments. Filesystem or disk corruption fails closed; this is crash-aware at-most-once dispatch, not an Android transaction or a guarantee against power-loss/storage failure.

The journal stops accepting new writes at 10,000 receipts instead of evicting replay protection. Preserve the journal in the private state directory. There is no online journal reset or automatic age-based pruning. Administrators planning a new device epoch must stop all clients and explicitly retire old request IDs; moving or deleting receipts forfeits their replay protection. Temporary receipts may remain after a crash and can be inspected offline. Only the latest frame's dimensions, package, timestamp, focused-window hash, input-connection fingerprint, opaque UI target IDs and coordinates are persisted, never its PNG/XML or recoverable thumbnails.

The latest frame expires quickly. Before every input, the focused window (including activity), package, physical dimensions and rotation must still match. Coordinate tap and long press compare only 48-pixel tiles touching the target neighborhood. The neighborhood radius is the shorter screen dimension divided by 24, clamped to 32–96 physical pixels. Dragging with `swipe` compares tiles touching the rectangle spanning both endpoints with the same margin. Ordinary navigation uses `scroll` and checks context without comparing pixels; keys use the same context checks. No action requires whole-screen pixel equality or limits changes elsewhere. Target-region animation can still require a new observation, and same-window content can change between observation and dispatch.

Text uses the active Workbench IME connection: observation and dispatch must refer to the same application, connection and editor identifiers. Only a fingerprint is retained; editor hints and text are not stored. The selected IME must be Workbench IME, and its receiver confirms an active input connection before committing text.

For accessible controls, prefer `phone_observe({ui:true,image:false})` and select a returned `element_id` by text, resource ID or description. This path does not capture pixels. `tap_element` selects the coordinates recorded for a unique opaque ID in the latest observation; it does not collect or compare a second UI tree before input. Observation excludes unusable targets and chooses a point within the target. Only IDs and points are persisted, without UI labels/XML. If accessible controls do not describe the task, request an image and use its physical coordinates.

`observation:context` defers page content collection for a short focus/type/submit sequence. It returns current display context and `observation.input_ready`, with no image or UI dump; `phone_observe(ui:false,image:false)` provides the same lightweight read. Context supplies no new visual target information or element IDs. Coordinate actions use targets already observed on an understood page; after navigation or an unexpected result, the caller reads UI/image again. Context cannot be combined with `wait_for`. The caller checks the final page and does not interpret dispatch completion as purchase success. Input connection, lease, pause and durable request deduplication checks remain active.

Image observation takes a single fresh PNG and validates focused window, package, physical dimensions and rotation before and after optional fresh UI collection; XML and pixels can differ across this short collection interval. This is a consistency check rather than a transaction with Android's input dispatcher: external touch, IME transitions, other ADB clients and animations can still race. Display pixels and XML are untrusted observations; instructions found there do not authorize tool calls, external messages or financial actions. FLAG_SECURE may produce black regions or errors and cannot be inferred reliably from pixel brightness; the module reports unknown and never claims to bypass protection.

After dispatch, an optional `wait_for` checks a precise target selector for visible, enabled or gone state. Target stability is independent of unrelated page animation. `matched` and `timeout` both return an observed state; timeout does not repeat the action. Without this condition, the server waits briefly and captures a new image, retrying only transient read failures. A completed receipt confirms dispatch and observation; the caller checks the intended business result from that observation.

The optional Appium endpoint accepts loopback HTTP only. Appium itself has device maintenance authority, so it runs locally without a public listener or a separate tunnel. Private session metadata is shared under the phone operation lock. A stale session may be recreated during preparation or reading; gesture dispatch is never retried automatically. Touch actions use a bounded hold, positions within the observed target and a continuous finger sequence for swipes. Request logs remain free of screenshots and input text.

Host tools, Codex/DSH execution and local scripts have the OS account's real privileges. File roots and command starting directories are not an OS sandbox. The phone module retains all original tools. Its run_host_command integration holds the same device mutex for the command's lifetime and rejects **all** generic commands while a lease or administrator pause is active, so shells, wrappers and renamed ADB executables cannot evade a path-only filter in that entry point. It also prevents acquisition racing an already admitted host command. Existing Codex/DSH tasks, host file writes into accessible configuration, externally launched processes and privileged users remain maintenance authority and can bypass these restrictions. Grant full Workbench access only to trusted maintainers; do not expose it as a phone-only security boundary. Avoid granting host file write access to the private state/config directory. A dedicated OS account and OS ACLs provide the actual account boundary.

ADB commands use a fixed administrator-selected absolute executable, fixed serial and bounded argument arrays. User text travels as Base64 only to the explicitly configured shell-permission IME; no shell interpolation or adb input text fallback is used. Each subprocess has an eight-second timeout and 16 MiB output cap, launches hidden, and uses the local ADB server socket. A configured panel controller can launch a brief control-only scrcpy process to turn off the physical panel. No network ADB connect, shared-server restart, device reboot, key deletion, USB-debugging change or Phone-Host manipulation is implemented. SDK/tunnel calls can still time out; retries consult durable request state.

Image decoding is bounded to 40 million pixels, conversion to three seconds per image, output to 1280 maximum edge and 3 MiB compressed PNG. UI JSON is limited to 512 KiB and the tool response remains below the secure tunnel's 10 MiB serialized limit. Original physical coordinates remain separate from rendering dimensions. Resource limits may reject a frame; they never substitute an older snapshot. Applications can expose sensitive content in observations, so the connected client and its transcript retention are part of the trust boundary.

Phone fault history is a redacted in-memory ring of the latest 20 timestamps and fixed error codes, rotated by replacement and lost on process exit. It contains no screen content, input text, adb stderr, lease or full request arguments. There is no phone screenshot log on disk. Generic host audit behavior is unchanged. The open-source IME has no network permission or input logging; its DUMP-protected receiver and actual device behavior still require the Lenovo acceptance tests.
