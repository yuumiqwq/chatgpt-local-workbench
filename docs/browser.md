# Optional OpenCLI browser control

Workbench invokes the installed OpenCLI browser CLI directly through Node and an argv array, without a shell or an agent turn. There is one browser backend: OpenCLI. It uses the already connected Edge profile's login through the OpenCLI extension; it does not install a browser, import cookies, bind a foreground page or expose arbitrary scripts/CLI commands. Browser policy remains disabled by default.

Enable the existing host policy and configure `browser.enabled`, `allowed_hosts`, an absolute private `state_directory` on E:, `opencli_entry` pointing to the installed package's `dist/src/main.js`, and `opencli_context` using the exact connected context ID from `opencli profile list`. The tested CLI version is `1.8.8-yuumi.1`, the default `opencli_version`, with extension `1.0.27`; other versions fail explicitly pending compatibility verification. The daemon and selected profile must already be connected. Workbench does not restart them. Remove obsolete `profile_name` when migrating from the former separate-profile implementation. State/cache/temp files created by the wrapper remain in the private state directory and are excluded from host file read/write/export tools.

The five existing `browser_*` tools retain their input schemas and names in v1/v2. Create starts a UUID-named OpenCLI background session through `browser <session> --window background tab new`. Each additional tab gets its own session; every page operation includes the original `--tab` identity after checking that session's inventory. Existing user tabs are never bound or selectable through the API. Selection is logical within Workbench and never issues OpenCLI `tab select`. OpenCLI supplies its background automation container and session lease semantics; the wrapper does not manipulate native windows. Sessions are connection/Bridge-instance scoped, with at most 32 tabs and no cross-instance recovery.

Snapshots use OpenCLI `state`. Numeric `[N]` references are translated into fresh, connection-local `eN` references mapped back to the observed native reference; a new snapshot is required after every mutation. Click/fill/type require a successful exact/stable target receipt, and fill also requires value verification. Snapshot target scoping, custom depth and hidden-text waits return `BROWSER_UNSUPPORTED`; default snapshots, literal text filtering and visible-text waits are supported. Page content remains untrusted and observation output is partial. No arbitrary selector or JavaScript is accepted through the public tools.

Calls are serialized and bounded to the configured deadline, with a combined stdout/stderr limit of 1 MiB and a returned text limit of 4–64 KiB. stderr and inherited credentials are not exposed. The wrapper never retries a command; OpenCLI's own transport behavior belongs to the pinned CLI/extension contract. Lost/ambiguous delivery or an unverified mutation blocks further mutation until observation. Cancellation terminates the CLI wait, not an already dispatched browser action. Cleanup releases only wrapper-created session IDs, with a five-second budget. Unconfirmed cleanup retains private `lease.json` for local recovery rather than guessing or replaying. Daemon PID changes and lost page identities invalidate the lease.

Tests use a mock OpenCLI command boundary plus real Node subprocess checks for literal argv, output bounds and cancellation, and exercise both public name profiles. Installed CLI help/version and daemon/profile metadata can be checked without GUI interaction. This release has not performed live signed-in browser acceptance; deployment and a local-page background smoke remain separate. Code push does not enable policy, restart an active Bridge or refresh client metadata.
